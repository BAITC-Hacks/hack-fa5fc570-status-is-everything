## 1. Паспорт проекта и контекст задачи

* **Кейс:** Agentic AI для прогнозирования почасовой выработки ветроэлектростанции (ВЭС) на горизонте 24–48 часов.
* **Заказчик:** АО «Самрук-Қазына» / АО «Самрук-Энерго».
* **Объект:** Шелекская ВЭС, Енбекшиказахский район, Алматинская область, Казахстан (Шелекский ветровой коридор).
* **Мощность кластера:** 2 турбины по 2.5 МВт (суммарно 5.0 МВт).
* **Точные координаты (декодированы из Google Maps):**
  * **Турбина 1:** `43.645150°N, 78.535604°E`
  * **Турбина 2:** `43.643198°N, 78.538828°E`
* **Обучающий период:** 11 марта 2023 г. — 31 января 2026 г. (10-минутные данные SCADA, 142k+ и 149k+ строк).
* **Тестовый период:** **1 февраля 2026 г. — 28 февраля 2026 г.**
* **Бизнес-цель:** Минимизация штрафов за небалансы на Балансирующем рынке электроэнергии Казахстана (БРЭ под управлением KEGOC) и предотвращение аварийных ситуаций при штормовых ветрах (>22 м/с).

## 3. Спецификация интерфейсов и модулей (API Contracts)

При разработке новых фич **не ломайте** следующие ключевые интерфейсы:

### А. `src/weather_service.py` (`WeatherService`)
- `get_forecast_as_of(as_of_date: str, horizon_hours: int = 48) -> pd.DataFrame`
  * Возвращает DataFrame с колонками: `timestamp`, `wind_speed_10m`, `wind_speed_100m`, `temperature_2m`, `surface_pressure`, `relative_humidity_2m`.
  * Использует кэш `data/weather_cache/february_2026_forecast.csv` (гарантирует 100% работу офлайн).
- `simulate_weather_update(base_forecast: pd.DataFrame, shift_hours: int = 12) -> pd.DataFrame`
  * Симулирует поступление обновлённого численного прогона метеомодели со смещением фронта.

### Б. `src/physics_features.py`
- `calculate_air_density(temp_c, pressure_hpa) -> np.ndarray` — расчет $\rho = P / (R \cdot T)$.
- `normalize_wind_speed_iec(v, rho) -> np.ndarray` — нормализация $v_{norm} = v \cdot (\rho / \rho_0)^{1/3}$ по стандарту IEC 61400-12.
- `extract_physics_features(df, wind_col, temp_col, pressure_col) -> pd.DataFrame` — обогащение датафрейма аэродинамическими и суточными фичами.

### В. `src/model.py` (`WindTurbineForecaster`)
- `forecast_weather(weather_df: pd.DataFrame) -> pd.DataFrame`
  * Выдает прогноз мощности `power_t{num}` в диапазоне $[0.0, 1.0]$ и доверительные границы `power_t{num}_lower`, `power_t{num}_upper`.
  * Содержит жесткие физические guardrails: при $v < 2.5$ м/с мощность $= 0$; при $v > 24.0$ м/с мощность $= 0$ (storm cut-out).

### Г. `src/agent.py` (`WindFarmAgent`)
- `execute_agent_cycle(as_of_date: str, horizon_hours: int = 48, simulate_update: bool = False) -> dict`
  * Возвращает словарь с ключами:
    * `forecast` (DataFrame с почасовым прогнозом в МВт и КИУМ);
    * `updated_forecast` (DataFrame скорректированного прогноза при обновлении погоды);
    * `audit` (словарь рисков: `STORM_CUT_OUT`, `ICING_RISK`, `CALM_PERIOD`, `HIGH_RAMP_RATE`);
    * `delta_mwh` (корректировка генерации в МВт·ч при повторном пересчете);
    * `reports` (сводки диспетчера на `ru` и `kz`);
    * `trace_logs` (список шагов рассуждения для отображения в UI).

## 4. Бэклог задач для тиммейтов и их AI-агентов (Modular Extensions)

Выберите одну или несколько задач ниже для параллельной реализации в ветках `feature/*`:

### Задача 1: Интеграция LLM Copilot (OpenAI / NVIDIA API)
* **Цель:** Использовать гранты хакатона ($50 OpenAI / $50 NVIDIA API) для генерации экспертных аналитических отчетов и чата с диспетчером.
* **Что сделать:**
  * В файле `src/agent.py` расширить метод `tool_generate_dispatch_report()`.
  * Если задан `OPENAI_API_KEY` или `NVIDIA_API_KEY`, отправлять структурированный JSON с прогнозом и аудитом в LLM (напр. `gpt-4o` или `meta/llama-3-70b-instruct`) с промптом энергетического эксперта АО «Самрук-Энерго».
  * В `app.py` добавить окно интерактивного чата («Спросить AI-энергетика о графике генерации»).

### Задача 2: Оптимизация накопителя энергии (BESS / Battery Simulation)
* **Цель:** Усилить бизнес-ценность для Самрук-Казына (критерий 15 баллов).
* **Что сделать:**
  * Создать модуль `src/bess_optimizer.py`.
  * Смоделировать аккумуляторную батарею (напр. 2.0 МВт / 4.0 МВт·ч), которая заряжается в часы избыточного ветра / низких цен БРЭ и разряжается в часы спада ветра и пиковых тарифов ЕЭС Казахстана.
  * Добавить вкладку «Симуляция BESS» в `app.py`.

### Задача 3: Геопространственная визуализация (GIS / Leaflet / PyDeck)
* **Цель:** Повысить визуальное качество и наглядность дашборда.
* **Что сделать:**
  * В `app.py` добавить интерактивную спутниковую карту (через `folium`, `pydeck` или `plotly.express.scatter_mapbox`) с точками Турбины 1 (`43.645150, 78.535604`) и Турбины 2 (`43.643198, 78.538828`).
  * Отображать вектор направления ветра (роза ветров) и тепловую карту скорости потока по Шелекскому коридору.

### Задача 4: Экспорт официальной заявки для Системного оператора (KEGOC Export)
* **Цель:** Практическая применимость решения.
* **Что сделать:**
  * Добавить кнопку «Скачать суточный диспетчерский график (XML / Excel)» в формате макета подачи заявок на Балансирующий рынок электроэнергии РК.

## 5. Правила работы с Git для всей команды

1. Перед началом работы всегда делайте актуализацию:
   ```bash
   git pull origin main
   ```
2. Создавайте тематическую ветку:
   ```bash
   git checkout -b feature/ваша-фича
   ```
3. Все зависимости добавляйте в `requirements.txt`.
4. Проверяйте запуск дашборда перед коммитом:
   ```bash
   streamlit run app.py
   ```
5. Вливайте изменения через pull request или быстрый merge без конфликтов в `main`.
