# Контракт погодного адаптера

`data/weather/forecasts.csv` хранит реальные численные прогнозы, один выпуск на issued_at для каждой турбины.
Поля: turbine_id, issued_at, available_at, valid_time, wind_speed, temperature.
forecast_origin добавляет координатор при выборе выпуска. Для прямого вызова predict_power это поле обязательно.
Все времена погоды обязаны иметь явное UTC-смещение: например ISO 8601 с Z или +05:00.
valid_time — начало прогнозируемого часового интервала, strictly > forecast_origin.

issued_at — документированное время выпуска модели. available_at — доказуемое время доступности выпуска потребителю, не ранее issued_at.
Нельзя приравнивать available_at к issued_at без основания. Нельзя использовать время скачивания сегодня как доказательство доступности в феврале.
Все строки одного выпуска должны иметь одинаковое available_at. Дубликаты и конфликтующие записи отклоняются.
Выбирается последний доступный выпуск; неполный новый выпуск приводит к отказу, а не скрытой подстановке старого.

`data/weather/source.json` — манифест (ниже схема, не реальные данные):

```json
{
  "kind": "numerical_forecast",
  "provider": "ИМЯ ПРОВАЙДЕРА И МОДЕЛИ",
  "source_url": "ССЫЛКА НА КОНКРЕТНЫЙ АРХИВ/ЭКСПОРТ",
  "availability_evidence": "ИСТОЧНИК ДОКАЗАТЕЛЬСТВА available_at ДЛЯ ВЫПУСКОВ",
  "wind_speed_unit": "m/s",
  "temperature_unit": "degC",
  "wind_height_m": 100,
  "scada_wind_compatibility": "ПОДТВЕРЖДЕНИЕ ВЫСОТЫ ИЛИ ДОКУМЕНТИРОВАННОЕ ПРЕОБРАЗОВАНИЕ",
  "sha256": "SHA256 ТОЧНЫХ БАЙТОВ forecasts.csv"
}
```

Число 100 в схеме — пример, не установленная высота SCADA. Заполнить по реальным данным источника.
Каждое обновление CSV должно сопровождаться обновлением SHA256 манифеста. Координаты задать только после подтверждения.
Сохраняйте архив старых выпусков: он нужен для воспроизводимого выбора по forecast_origin.

Проверка хеша PowerShell: `(Get-FileHash data/weather/forecasts.csv -Algorithm SHA256).Hash.ToLower()`.
Запуск наблюдения: `.\.venv\Scripts\python.exe -m src.agent --watch`.
Подключение источника — отдельная задача. Текущий адаптер намеренно не загружает сомнительный старый кэш или реанализ.

## Previous Runs: исследовательские срезы

`python -m src.previous_runs` получает из Open-Meteo отдельные значения,
спрогнозированные за 24 и 48 часов до каждого целевого часа. Архив сохраняется
в `data/weather/diagnostics/` и не читается рабочим `WeatherService`.
Previous Runs не указывает точное время инициализации конкретного прогона и
время его исторической доступности. Поэтому `valid_time - 24/48 часов` нельзя
записывать как доказанный `issued_at` и нельзя подменять им `available_at`.
Эти данные годятся для отдельной иллюстрации «погода → мощность» с пометкой о
номинальном горизонте, но не проходят строгий исторический контракт выше.
Для точного воспроизведения выпуска нужна модель Single Runs с подтверждённой
историей доступности. В Single Runs параметр `run` — время инициализации,
которое само по себе также не доказывает время публикации.
