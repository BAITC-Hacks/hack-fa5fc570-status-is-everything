## 🌬️ О проекте

**WindMind AI** — интеллектуальная агентная система для прогнозирования генерации ветроэлектростанций и поддержки решений диспетчера.

Система не ограничивается одной ML-моделью.

WindMind самостоятельно выполняет полный цикл:

**Прогноз погоды → Проверка данных → Физические признаки → ML-прогноз → Анализ рисков → Пересчёт → Диспетчерская сводка**

Цель проекта — заранее показать оператору ВЭС:

- сколько электроэнергии произведут турбины;
- как будет изменяться генерация каждый час;
- насколько устойчив прогноз;
- какие погодные и эксплуатационные риски могут возникнуть;
- как изменится прогноз при поступлении новых погодных данных.

# 🎯 Проблема

Выработка ветровой электростанции напрямую зависит от погодных условий.

Скорость ветра может значительно измениться всего за несколько часов, поэтому оператору недостаточно знать:

> «Завтра будет сильный ветер».

Ему необходимо понимать:

> **«Сколько электроэнергии наша ВЭС произведёт в каждый час следующих 24–48 часов?»**

Неточный прогноз генерации усложняет планирование работы ВЭС и может увеличивать отклонение фактической генерации от запланированной.

Дополнительно диспетчеру важно заранее видеть потенциально опасные или нестандартные условия:

- штормовой ветер;
- недостаточную скорость ветра;
- риск обледенения;
- резкие изменения мощности;
- изменение ожидаемой генерации после обновления прогноза погоды.

# 🤖 Как работает Agentic AI

WindMind построен как последовательность специализированных инструментов, которыми управляет основной агент.

## 1. Weather Scout

Получает погодные данные для координат двух турбин и формирует метеорологические признаки на необходимый горизонт прогнозирования.

Используются, в частности:

- скорость ветра;
- температура воздуха;
- атмосферное давление;
- дополнительные погодные параметры.

---

## 2. Physics Feature Engine

Погодные данные преобразуются в физически осмысленные признаки.

Рассчитываются:

- плотность воздуха `ρ(T, P)`;
- нормализованная скорость ветра;
- энергетический потенциал ветра `v³`;
- дополнительные полиномиальные признаки;
- временные циклические признаки.

Так ML-модель получает не только исходные значения погоды, но и признаки, связанные с физикой ветровой энергетики.

---

## 3. ML Forecaster

Для каждой турбины используется отдельная модель **LightGBM**.

Модель прогнозирует нормализованную активную мощность, после чего результат переводится в физическую мощность в МВт.

Используются физические ограничения, не позволяющие прогнозу выходить за допустимый диапазон мощности турбин.

---

## 4. Risk & Safety Auditor

После формирования прогноза агент автоматически анализирует потенциальные риски.

Проверяются:

- ⚠️ штормовые условия;
- 🧊 потенциальный риск обледенения;
- 🌬️ слишком низкая скорость ветра;
- 📉 резкие изменения мощности;
- ⚡ потенциально нестабильные интервалы генерации.

Важно: данные предупреждения являются инструментом поддержки решений и не заменяют штатные системы защиты турбин.

---

## 5. Event-Driven Recalculation

Погодный прогноз может измениться.

Поэтому WindMind умеет автоматически повторять прогнозный цикл после обновления входных данных.

```text
Обновилась погода
        ↓
Новые погодные данные
        ↓
Пересчёт физических признаков
        ↓
Повторный ML-прогноз
        ↓
Повторный Risk Audit
        ↓
Сравнение прогнозов
        ↓
Расчёт ΔМВт·ч
        ↓
Обновление диспетчерской сводки
```

Таким образом, система работает не как статическая ML-модель, а как **событийно-управляемый прогнозный агент**.

# 🧠 Physics-Informed Machine Learning

WindMind объединяет машинное обучение с физикой ветроэнергетики.

Плотность воздуха рассчитывается на основе температуры и давления:

`ρ = P / (R × T)`

Энергетический потенциал ветра связан с кубом скорости:

`Power ∝ v³`

Эти признаки используются совместно с историческими SCADA-данными для построения прогноза мощности.

Таким образом, модель учитывает не только статистические зависимости, но и физически осмысленные характеристики воздушного потока.

# ⚠️ Ограничения текущей версии

WindMind является прототипом, разработанным в рамках HackAlem AI.

Текущая версия имеет следующие ограничения:

- моделирование выполняется для двух турбин мощностью 2,5 МВт каждая;
- отсутствуют некоторые эксплуатационные SCADA-параметры;
- в предоставленных исторических данных отсутствует направление ветра;
- wake effect для полного ветропарка пока не моделируется;
- данные о техническом обслуживании и доступности оборудования требуют дополнительной интеграции;
- предупреждения системы предназначены для поддержки решений и не заменяют штатные системы безопасности ВЭС.

Для промышленного внедрения потребуется интеграция с live-SCADA, техническими характеристиками турбин, данными доступности оборудования и промышленными погодными сервисами.
